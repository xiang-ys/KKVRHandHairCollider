# 0.6.4 accessory contact TDD evidence

## Source and journey

The journey came from an in-game report that skirts moved from character
animation but did not react when a stationary controller was placed against
them, followed by the requirement to give every physical accessory an
appropriate contact response without replacing native body physics.

## RED

- Checkpoint: `8888577 test: reproduce missing accessory contact profiles`
- Command: `dotnet run --project tests/KKVRHandHairCollider.Tests.csproj -c Release`
- Result: expected RED because accessory-specific tuning, root union,
  body-physics classification, and bounded accessory simulation did not exist.

## GREEN

- Checkpoint: `087a076 fix: add adaptive contact physics for accessories`
- Command: `dotnet run --project tests/KKVRHandHairCollider.Tests.csproj -c Release`
- Result: `ALL TESTS PASSED` (36/36).
- Command: `dotnet build src/KKVRHandHairCollider.csproj -c Release`
- Result: succeeded with 0 warnings and 0 errors.

## Review refactor

- Checkpoint: `bd0c433 refactor: preserve converted accessory physics roots`
- A source review found that clothes-to-accessory tools can legitimately bind
  an accessory DynamicBone to a character-bone root. The initial ownership
  check would have rejected those components after changing coordinates.
- The review regression was reproduced, the ownership condition was removed,
  and exact native body-physics exclusions were retained. The full suite stayed
  green.

## Extended simulation

The release test executable was run ten consecutive times with no failures.
This exercised 1,000,000 randomized accessory-contact samples in addition to
the existing trajectory, force, grab, binding, and lifecycle regressions.

## Known gap

The pure .NET harness cannot render the exact modded accessory inside Unity.
The runtime logs therefore report accessory scan counts, disabled/rootless
components, excluded body references, and bounded component/root examples once
per changed signature. No coverage collector is configured for this net35
console harness, so no percentage is claimed.
