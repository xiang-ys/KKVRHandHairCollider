# 0.6.2 lifecycle fixes TDD evidence

## Source and journeys

The journeys were derived from the local Claude Code review and independently
verified against the current source, installed assemblies, and KK_Colliders
source. No external plan file was used.

- As a player, disabling an interaction feature must remove only the bindings
  and force targets owned by this plugin.
- As a KK_Colliders user, the plugin must reuse the real arm collider objects
  without fighting KK_Colliders skirt behavior.
- As a player changing scenes or VR rigs, stale Unity object references must not
  block controller discovery or accumulate Cloth collision pairs.

## Guarantees

| # | Guarantee | Test |
|---|---|---|
| 1 | Real `KK_Colliders_*` arm names are recognized; thighs are rejected | `recognizes real KK_Colliders names` |
| 2 | Character arm colliders never enter skirt binding sources | `skirt sources exclude character arm colliders` |
| 3 | Disabled, missing, and outfit-replaced force targets are removed | `target registry removes disabled and missing targets` |
| 4 | Destroyed Unity references use a lazy live fallback | `Unity reference fallback treats destroyed objects as missing` |
| 5 | Dead/obsolete managed Cloth pairs are removed while foreign live pairs remain | `cloth binding sync removes stale managed pairs` |
| 6 | Owned colliders require both plugin and feature switches | `owned collider enablement follows both switches` |
| 7 | Plugin fallback hand colliders are distinguishable from KK_Colliders objects | `identifies plugin fallback hand colliders` |

## Coverage and gaps

The repository has no coverage collector configured for the net35 executable
test harness. The 29 tests include 320,000 deterministic velocity-force steps
and 100,000 grab-force samples. Unity runtime lifecycle behavior is additionally
checked through Release build, assembly inspection, and unattended game startup;
the startup does not enter a character scene, so headset visuals and live outfit
binding counts remain unverified.
